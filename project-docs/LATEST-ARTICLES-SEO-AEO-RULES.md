# TPJ「最新記事」専用 SEO・AEO制作ルール

- バージョン：1.1（2026年11月8日、既存ルールとの競合解消を反映。初版は1.0・2026年11月5日制定）
- 制定日：2026年11月5日
- 対象：Third Place Japan（TPJ）トップページの「最新記事」セクションに今後掲載する新規記事
- 適用外：既存記事の一括改修、TPJ Stories全体のカテゴリ・URL構造変更、認証審査基準の変更
- **既存ルールとの関係**：ルート`CLAUDE.md`と内容が重複・抵触する場合は、本ファイルを独自に適用せず、まず既存ルールとの整合を確認する（2026-11-08にmeta description文字数・本文文字数の対象範囲・FAQ・内部リンク本数の4点を確認済み。詳細はルート`CLAUDE.md`「制作方針の参照先」直下の記載を参照）

## 1. 目的と編集方針

最新記事を、単なる地域紹介から、**【地域】×【業種】×【目的】を軸に【体験】×【属性】を加えた、具体的な場所選びを支援する記事**へ発展させる。目標は①自然検索からの流入、②AI検索での理解・引用機会、③関連施設への送客、④TPJの信頼性・ブランド形成、⑤将来の「地域・エリア×15カテゴリ」デジタル不動産への接続である。

SEO/AEOは掲載・引用を保証するものではない。読者に役立つ一次情報と検証可能な事実を最優先する。

## 2. 対象と変更範囲

- 新たに「最新記事」へ掲載する記事に本ルールを適用する。過去記事は明示的な依頼がない限り変更しない。
- トップページの既存表示（大カード2件＋小カード6件）とデザインを原則維持する。
- 新規カテゴリ、既存URL変更、サイト全体のテンプレート変更は事前承認を必要とする。
- 最新記事の表示対象は既存の公開日時・並び順ロジックを確認して決定する。未来日付記事が意図せず表示されないようにする。

## 3. 記事企画の決定ルール

1. 地域を一つ定める（例：表参道・青山）。地理的範囲を曖昧にしない。
2. 15カテゴリのうち主カテゴリを一つ定める（例：カフェ）。既存の公式分類名を使用する。
3. 利用目的を一つ明確化する（例：2〜3名の商談）。必要なら副目的を一つ追加する。
4. 体験・属性を自然に補う（例：静かな会話／出張者）。全要素をタイトルに詰め込まない。
5. 検索需要、紹介できる施設情報、既存記事との重複、地域ハブへの接続を確認する。
6. 条件に合う施設を確認できない場合は、ランキング・おすすめ施設一覧を作らず「選び方」型の記事にする。

**例**：「表参道で静かに打ち合わせできるカフェの選び方｜商談・ランチミーティング向け」

## 4. タイトル・メタ情報

- titleタグ、H1、meta descriptionは記事固有の内容にする。
- H1は原則一つ。地域・業種・目的を自然に表現する。過度なキーワード反復は禁止。
- meta descriptionは**日本語記事は110〜120字に固定**する（TPJ全体の既存ルールに統一。2026-11-08確定）。160字まで許容すると検索結果で文末が「…」で切れ、一文目で結論を完結させても後半が見えなくなる実害が過去にあったため、字数固定を優先する。字数を満たしつつ、検索者が記事の内容と価値を判断できる自然な日本語で書く（詰め込みは避ける）。
- URLスラッグは簡潔で意味のある英単語をハイフンでつなぎ、既存サイトのURL規則に従う。
- canonical、OGP、公開日、更新日、著者・運営主体、パンくず、サイトマップを既存実装に沿って設定する。
- 更新日は実際に内容を更新した場合のみ変更する。公開日を偽装しない。

## 5. 推奨記事構成

文字数は**2,500〜3,500字程度を編集上の目安**とするが、情報が十分なら短くてもよい。水増し禁止。

**本ルールの文字数は「最新記事」向けの通常記事（地域×業種×目的の記事）にのみ適用する（2026-11-08確定）。** ピラー記事（既存ルール：本文2,800〜4,000字）・地域ピラー記事（既存ルール：本文4,000〜4,300字）には適用しない。トップページ「最新記事」に掲載されることだけを理由に、既存のピラー記事ルールを上書きしない。ピラー記事・地域ピラー記事として企画する記事は、本ルールではなくルート`CLAUDE.md`の該当ルールに従う。

1. **冒頭の直接回答**（目安120〜180字）：誰に、どんな条件が適するかを簡潔に回答。
2. **選び方の条件**：目的に直結する判断軸（静寂性、席の広さ、設備、予約可否、食事など）。
3. **地域固有の事情**：駅・動線・混雑・地域特性。根拠のない断定は避ける。
4. **確認済み施設の紹介・比較**：掲載できる場合のみ、条件・選定理由・情報確認日を明示。
5. **サードプレイスの視点**：TPJ公式の7軸評価の定義を変更せず、記事テーマに関連する軸を説明。未審査施設に認証・公式評価を付与しない。
6. **FAQ**：検索者の具体的な疑問に回答。
7. **まとめ・CTA**：関連エリア・カテゴリ・TPJセレクト・施設詳細への自然な導線。

見出し数や順番は検索意図に合わせて調整可能。比較表は根拠のある項目だけで構成する。

## 6. FAQ専用ルール

- **基本5問、目安4〜6問**。質問が少ないテーマでは無理に増やさない（2026-11-08確定）。問数よりも、検索者の疑問に明確に回答する品質を優先する。既存の「Q&Aは任意」という全記事共通ルールと矛盾しない、「最新記事」向け通常記事のサブセット向け追加基準として適用する。
- 各回答は目安80〜140字。最初の一文で直接答え、必要な条件や例外を補う。
- 「場所の選び方」「人数・利用条件」「設備」「予約・混雑」「TPJ独自の視点」など、本文を補完する質問を優先。
- FAQは本文に表示し、本文と矛盾させない。重複質問・宣伝的な質問を避ける。
- FAQPage JSON-LDは既存の技術方針と検索エンジンの適用条件を確認して判断する。FAQリッチリザルトやAI引用の保証として扱わない。

## 7. SEOの実装チェック

- 検索意図に合った独自タイトル、見出し、冒頭回答
- 地域・カテゴリ・目的の語句を自然に使用
- 同じ検索意図を狙う既存記事とのカニバリゼーション確認
- 正しいcanonical、index設定、XMLサイトマップ、パンくず
- 関連性の高い内部リンク（存在確認必須）。本数は既存のルート`CLAUDE.md`「内部リンク（AEO対策・毎回必須）」ルールをそのまま適用する：新記事→既存記事へ3〜4本（ユニークURL数基準）、既存記事→新記事への逆リンクを2〜3本。本ファイル独自の本数基準は設けない（2026-11-08確定）
- 画像の権利・出典確認、内容を説明するalt、適切なサイズ・読み込み
- モバイル表示、読みやすさ、ページ速度、リンク切れの確認
- Search Consoleで公開後のインデックス・表示回数・クエリ・CTR・掲載順位を確認

## 8. AEO・構造化データ

- 読者の問いに冒頭・各見出し直下で明快に回答する。
- 施設の事実、編集部の見解、推測を区別する。
- 独自性を出す：現地確認、一次資料、比較条件、確認日、TPJの評価観点など。
- 記事に合うArticleまたはBlogPosting、BreadcrumbList等のJSON-LDを検討。実ページの可視情報と一致させる。
- LocalBusiness等の施設データは、実在施設の確認済み情報に限り、適切な対象ページに実装する。
- JSON-LDの構文・整合性を検証し、構造化データだけでAI推薦されると説明しない。
- AI検索への露出は固定質問セットで継続観察し、**TPJの引用**と**施設の推薦**を別々に記録する。

## 9. 施設情報・品質・中立性

- 実在施設の所在地、営業時間、Wi-Fi、電源、予約可否、ペット条件などは公式情報や現地確認に基づく。
- 未確認事項は「未確認」とするか記載しない。架空の口コミ・体験・ランキング・取材実績を作らない。
- 施設紹介時は確認日、選定条件、根拠をできる限り明記する。
- TPJセレクト掲載、広告掲載、認証グレードは区別する。広告枠購入が評価・認証・編集推薦を決めない。
- 画像は権利処理済みのものを使用。出典を必要に応じて記載する。

## 10. 「最新記事」カード表示ルール

- 大カード2件＋小カード6件の現行レイアウトを維持。
- カードには記事固有の画像、カテゴリまたは「カテゴリ×目的」、地域、読みやすい抜粋、公開日を表示。
- 抜粋は地域の一般論ではなく、**誰のどの目的を解決する記事か**を優先。
- 小カードでは文字切れを想定し、重要な意味が先に伝わる文面にする。
- 既存デザイン・レスポンシブ表示・アクセシビリティを壊さない。

## 11. 内部リンク・送客・デジタル不動産

記事 → 地域ハブ → カテゴリハブ → TPJセレクト／施設詳細 → 施設公式サイト・予約ページ、という導線を基本とする。ただし存在しないページをリンクしない。

将来のデジタル不動産は「地域・エリア×15カテゴリ」の掲載枠として接続できるよう、記事側の地域・カテゴリ・目的・体験・属性を一貫したデータ項目で管理する。広告枠は明確に表示し、編集内容・認証とは独立させる。

## 12. 効果測定と改善

公開後は記事単位で以下を記録する。

- Search Console：表示回数、クリック数、CTR、平均掲載順位、検索クエリ
- GA4：自然検索流入、記事閲覧、内部リンククリック、施設詳細遷移、外部公式サイト・予約クリック
- AI検索：定点質問におけるTPJ引用の有無と施設推薦の有無（手動または適切な計測方法）
- 事業指標：掲載施設への送客、掲載事業者への報告可能な成果

**推奨レビュー時点：公開後14日・30日・90日。** 初期データが少ない場合は順位や成果を断定せず、タイトル・冒頭・内部リンク・施設情報を優先的に改善する。

## 13. VSコードでの作業手順

1. TPJリポジトリの既存記事テンプレート、カテゴリ、URL規則、日付処理、構造化データ、最新記事の表示ロジックを確認。
2. 記事の検索意図・対象読者・地域・カテゴリ・目的を決定。
3. 既存記事との重複と内部リンク候補を調査。
4. 本ガイドラインに沿って**新規記事1本**を作成。
5. 公開日・meta・canonical・パンくず・JSON-LD・FAQ・画像・CTAを検証。
6. ビルド、リンク、モバイル表示、構造化データを確認。
7. 作成ファイル、記事URL、文字数、FAQ数、内部リンク、検証結果、未確認事項を報告。
8. **コミット・プッシュ・本番公開は承認まで実施しない。**
