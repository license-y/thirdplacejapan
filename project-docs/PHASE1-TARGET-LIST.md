## 3. 優先順位の仕分けロジック

`CLAUDE.md` 11-10の優先度A/B/C基準を、現状のデータで機械的に判定できる形に
落とし込んだ。判定順序は以下の通り（上から優先適用）。

```
1. grade_slug が flagship、または実証店舗（isVerification） → 優先度A
2. 7軸スコア平均が 7.8 以上 → 優先度A
3. 7軸スコア平均が 6.5 以上 7.8 未満 → 優先度B
4. 7軸スコア平均が 6.5 未満 → 優先度C
```

**補足**：現状はほぼ全件が「7軸スコアは充足済み・一次情報は仕様通り薄い」
という同条件のため、`CLAUDE.md` 11-10が定める「認証グレード」「7軸評価データの
有無」という基準だけでは34件のTPJセレクトを差別化できない。そのため
本リストでは、11-10が定める基準のうち唯一この段階で施設間の差を持つ
**「7軸評価データ」（＝スコアの充実度そのものではなく、スコア平均値の高さ）**
を暫定的な主要な差別化軸として採用した。この判定ロジックは暫定運用であり、
以下が整備され次第、判定基準に組み込んで再評価すること。

- PV・検索流入の実測値（Search Console/GA4連携後）
- 「TPJブランドを代表する施設」の編集部合議判定（`CLAUDE.md` 11-10の
  判定プロセスに従い、個別に協議・記録する。本リストの機械判定はこれを
  代替しない）
- カテゴリ配分ガイドライン上の重要性（`CLAUDE.md`「カテゴリ配分ガイドライン」
  で目標比率を下回るカテゴリ＝コワーキング・宿泊・その他を優先発掘する方針との
  整合。今回のC群にコワーキング・貸切ヴィラが多いのは、これらのカテゴリでの
  掲載自体が新しく（`certified_date: 2026-08-07`が中心）、スコアの母数・
  検証期間がまだ短いことが一因であり、カテゴリとしての重要性の低さを意味しない）

**優先度別件数**：A＝8件／B＝17件／C＝10件（合計35件）

## 6. 優先度B・C群への展開スコープの明確化（2026-08-17追記・重要）

優先度A・8件の完了を受け、優先度B（17件）・C（10件）への構造化データ／
`last_verified_date`展開に着手するにあたり、着手前の技術検証を行った。

**検証結果**：27件全件について、構造化データ実装（LocalBusiness・
AggregateRating・Review・BreadcrumbList・7軸`additionalProperty`・`geo`）に
必要な技術的前提データ（7軸スコア・`lat`/`lng`・`category_slug`・
`certified_date`・`grade_slug`・`url`または`instagram_url`）に欠落は0件
だった。`venue.njk`は全35施設共通の単一テンプレートであるため、これらの
構造化データは実装作業を要さず既に27件全件で本番稼働済みであることも
実機確認済み（優先度Cで最もスコアが低い施設でも5ブロックのJSON-LD出力を
確認）。したがって、構造化データ実装は一次情報（本文・FAQ・タグ）の
充実を前提としない。

**一方で明記すべきリスク**：この技術判断の結果として、優先度B・C群27件は
「構造化データは実装済みだが本文・FAQは`TPJセレクト`仕様のまま薄い
（本文なし・タグ0個・FAQ2〜3問）」ページとして本番に並ぶことになる。
これは外形的に、`BUSINESS-MODEL.md`（非公開）が懸念する「量産による薄い
コンテンツ化」リスクと重なって見える構造である。以下を明記して記録する。

- 27件は「TPJセレクト仕様として意図的に軽い」状態であり、`CLAUDE.md`
  「TPJセレクト 掲載仕様」が定める正規の仕様に沿っている（欠陥ではない）。
  構造化データ・`last_verified_date`の展開と、一次情報（本文・FAQ・タグ）の
  拡充は**別トラックの独立した作業**であり、混同しないこと
- 一次情報拡充（本文・FAQ・タグの充実）の着手時期は、本追記時点（2026-08-17）
  では**未定**。優先度B・C群への構造化データ／`last_verified_date`展開を
  進めることが、一次情報拡充の着手を約束するものではない点に注意する
- **追記（2026-08-17・Phase1全35施設完了後）**：一次情報拡充トラックの
  優先順位・最低ライン・執筆主体・効果検証との切り分けを整理した計画を
