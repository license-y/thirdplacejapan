### 1-2. 「実装前」基準日をどう置くか（重要な注意）

上記の通り、優先度A・8施設のLocalBusiness／AggregateRating／
Review＋reviewRating／BreadcrumbList／7軸スコアという**中核の構造化データは、
今回のセッション（2026-08-17）より3〜6週間前から本番稼働していた**。
2026-08-17に新規実装・本番確認したのは`last_verified_date`フィールドのみ
である（`CLAUDE.md` 11-8参照）。

したがって「実装前 vs 実装後」を単純に2026-08-17で区切ると、以下の誤読
リスクがある。

- 中核スキーマは既に3〜6週間本番稼働しており、Googleのインデックス・
  AI引用に一定程度反映済みの可能性がある。2026-08-17を「構造化データが
  ゼロから実装された日」と誤認しないこと
- 2026-08-17を基準日にした観測は、実際には主に「`last_verified_date`という
  小規模な追加の限界効果」と「Phase 1優先度A・8件が揃ったことの確認」を
  測ることになる。構造化データ全体（中核スキーマ）の効果を測る観測には
  ならない点を認識した上で結果を解釈すること

### 1-3. 採用する基準日（確定）

上記を踏まえ、目的の異なる2つの基準日を使い分ける。

- **基準日A（中核スキーマ・参考値）＝2026-07-21**：7施設の中核スキーマが
  出揃った日。ただしこの日を境にした厳密なbefore/after測定は、当時この
  目的での観測を開始していなかったため、GSC等でデータが遡って取得できる
  場合の**事後的な参考点**に留める
- **基準日B（Phase 1効果検証の実務上の起点）＝2026-08-17（確定・採用）**：
  優先度A・8施設全件の構造化データ（`last_verified_date`含む）が出揃い、
  本番で確認できた日。本計画における定点観測は、この日を起点とする

### 1-4. 観測結果を報告する際の必須ルール（絶対厳守）

基準日Aとの比較、基準日Bとの比較は、**測っている対象がまったく異なる別の問い**
である。

- 基準日A（7/21）との比較 → 中核スキーマ（LocalBusiness・AggregateRating・
  Review・BreadcrumbList・7軸スコア等）全体が本番稼働してからの効果を測る
- 基準日B（8/17）との比較 → `last_verified_date`追加分＋Phase 1優先度A
  8件が揃った効果のみを測る（中核スキーマは基準日Bの時点で既に3〜6週間
  稼働済みのため、基準日Bとの比較では中核スキーマ自体の効果はほぼ
  含まれない想定）

**この2つを区別せずに「実装後に変化があった／なかった」とだけ報告すると、
どちらの効果を指しているのか読み手に伝わらず、誤った解釈（例：
`last_verified_date`という小さな追加だけで大きな検索表示の変化が
起きたかのような誤解）を招く。**

→ **観測結果を報告・記録する際は、必ず基準日A比較か基準日B比較かを明記する。**
「4. 記録テンプレート」にもこの明記欄を設ける。

## 3. 観測開始タイミング

- Googleが構造化データを認識し、リッチリザルト等に反映するまでは
  一般的に数日〜数週間を要する
- **初回定点観測：2026-08-31（基準日Bから2週間後）を目安とする**
  → **実施済み（結果は「7. 観測記録」参照）**
- 以降は`AEO-PLAYBOOK.md`「6. 効果測定」が定める月次のAI検索実査・
  Search Console確認のサイクルに合流させ、Phase 1専用の特別観測を
  都度別立てにしない
- **次回観測：2026-09-30を予定**（初回観測から1ヶ月後。以降は月次サイクル
  として継続する）
- 参考：GSCのクエリ別データが遡って取得できる場合は、基準日A（7/21）
  以降の指名検索・表示回数の推移も確認し、「中核スキーマ安定化」と
  「`last_verified_date`追加」それぞれの寄与を可能な範囲で切り分ける

### 3-1. 優先度B・C群を観測対象に含めるかどうか（未定・2026-08-17追記）

`PHASE1-TARGET-LIST.md`に基づき、優先度B（17件）への`last_verified_date`
実装が進行中である（本ファイル策定時点で優先度B 17件中17件が完了見込み）。
これにより、優先度A・8件以外の施設にも本計画と同種の構造化データ・
`last_verified_date`が揃いつつある。

しかし、**本計画（比較基準日A/B・観測項目・観測開始タイミング）の対象は
現時点でも優先度A・8件のみであり、優先度B・C群を将来的に観測対象へ
含めるかどうかは未定**。含める場合、対象施設ごとに`last_verified_date`
反映日が異なるため、基準日の設計を個別に検討し直す必要がある
（優先度A・8件の基準日A/Bをそのまま流用できない可能性が高い）。
優先度B・C群への展開作業自体は、効果検証の対象拡大を意味しない
（前回確認済みの「別トラック」原則をここでも維持する）。

**追記（2026-08-17・一次情報拡充トラック計画策定時）**：一次情報拡充
（本文・FAQ・タグ）の対象範囲を検討する過程で、**優先度A・8件のうち
7件（GBC以外）は優先度B・C群27件と同様に一次情報が薄いままである**
ことが判明した。もしこの7件に一次情報拡充を行うと、本計画の比較対象
（優先度A・8件）に構造化データ以外の変化が混入し、効果検証が無効化
される。そのため`PRIMARY-INFO-ENRICHMENT-PLAN.md`では、**一次情報拡充の
対象を優先度B・C群27件に限定し、優先度A・8件（GBC含む）は当面対象外と
する**ことを確定ルールとして定めた。本計画（比較基準日A/B・観測対象＝
優先度A8件）はこの決定と整合しており、変更していない。

**追記（2026-08-17・一次情報拡充27件完了時点での確認記録）**：優先度B・C群
27件全件（3バッチ）への本文・タグ追加が2026-08-17中に完了した
（`PRIMARY-INFO-ENRICHMENT-PLAN.md`参照）。この完了を受け、優先度A・8件
が本当に一切変更されていないかをセッション全体の`git diff`で機械的に
再検証した。結果、優先度A・8件の`venues.json`エントリに追加された行は
`last_verified_date`のみであり、本文・タグの追加は0件であることを確認した
（唯一の削除行は承認済みのhanare URL修正であり優先度A・B・Cいずれとも
無関係）。**したがって本計画の比較対象（優先度A・8件）は一次情報拡充
27件の実施によって汚染されていない。**

なお、上記の「優先度B・C群を観測対象に含めるかは未定」という論点を
将来検討する際に備え、一次情報拡充27件の完了日（2026-08-17）をここに
記録しておく。将来この27件を観測対象に含める場合、`last_verified_date`
反映日（8/14〜8/17）に加えて、この一次情報拡充完了日も基準日設計の
考慮要素になる。

## 6. 新規記事投稿ペースの制限（2026-08-17新設・期間限定）

### 6-1. 背景

2026-08-17、8/12〜8/17の6日間に8/12（町田市2本）・8/16（八王子市4本）の
計6記事が公開されていたことが判明した（いずれも本計画とは別セッションでの
作業）。サイト全体のクロール頻度・インデックス状況の変化が、優先度A・8施設
の構造化データ効果の観測結果（基準日B比較）に混入するリスクがあるため、
新規記事の投稿ペースを制限するルールを新設した。

### 6-2. ルール（確定）

- **2026-08-17〜2026-08-31（初回定点観測まで）は、新規記事の投稿ペースを
  週2〜3件程度に抑える**
- 対象はサイト全体の新規記事公開（`/stories/`配下の記事、venues.jsonの
  施設追加は対象外。施設の`last_verified_date`更新や既存本文の軽微な修正も
  対象外）
- ルート`CLAUDE.md`「記事執筆開始時の確認事項（必須）」に同内容を転記済み。
  記事執筆に着手するセッションは、着手前にこのペース制限を確認すること
- 8/31の初回観測後、結果を確認してからペースを見直す（本節を更新する）

### 6-3. 品質面で発見した副次的な問題（是正は8/31以降に延期）

上記6記事の品質を機械チェックした結果、八王子市4本（禅体験・神社寺院・
インバウンド・文化レジャー編）すべてが、答えリード（記事冒頭）とまとめ
（記事末尾）の両方に「〇〇の核心は、〜ではなく、〜にある。」という
同一の文型を使っており、1記事内でリードとまとめがほぼ同一文になっている
ことが判明した。また同じ4本のうち2本（禅体験編・神社寺院編）には結び文
「サードプレイスジャパンは、この〜を7軸評価基準で評価している。」があるが、
残り2本（文化・スポーツ・レジャー編・インバウンド編）には無いという
バッチ内の不揃いも見つかった。

該当ルールはルート`CLAUDE.md`「文体ガイドライン（TPJ編集部）」の
「答えリードとまとめの言い換え不足を避ける」「結び文の一貫性」として
新設済み（今後の新規記事・既存記事修正に適用する）。

**八王子市4本の実際の文面修正は、8/31の初回観測後、新規記事の投稿再開
判断とあわせてまとめて対応する。** 8/31の観測直前に既存記事へ変更を
加えると、新規記事投入を抑制した意図（サイト全体の変化を最小化し観測結果
の解釈をクリーンに保つ）と矛盾するリスクがあるため、記録のみに留め、
今回は着手しない。

## 7. 観測記録

### 観測記録：2026-08-31（初回定点観測）

**比較基準日：基準日B（2026-08-17・`last_verified_date`＋優先度A8件が揃った日）**

**次回観測予定：2026-09-30**（本観測から1ヶ月後。以降は`AEO-PLAYBOOK.md`
「6. 効果測定」が定める月次のAI検索実査・Search Console確認サイクルに
正式に合流させ、Phase 1専用の特別観測を都度別立てにしない。3節参照）。
**2026-08-31中にGSC「URL検査」の結果が判明し「順位問題」として確定した
ため（下記7参照）、9/30観測の主要観測項目は「個別施設名クエリでの
掲載順位に変化が出てきたか」とする。**

**この観測の位置づけ（必読）**：本記録は基準日Bから2週間後の初回定点観測であるが、
**基準日B時点でGSC/GA4の定量スナップショットを取得していなかった**ため、
指名検索インプレッション・クリック数・CTR・コンバージョンについては
「基準日Bと本日の数値を比較した結果」ではなく、**「運用者が今後Search Console
で2026-08-17〜2026-08-31の期間を遡って取得し、直前の同期間（例：2026-08-03〜08-16）
と比較する」という基準日B比較の実務が、この観測をもって開始される**という位置づけである。
Search ConsoleはUI上で過去に遡った期間のクエリ別データを取得できるため、
遡及的な基準日B比較は運用者が実施すれば技術的に可能。今回未実施なのは

3. **技術監査（2026-08-31実施・ユーザーからの確認依頼への対応）**：上記1で
   個別施設ページが検索結果に出現しなかったことを受け、「意図的な

   |---|---|

   いずれも403 Forbiddenで拒否された（Cloudflareのボット保護がWebFetch
   ツールを弾いているためと考えられ、サイト側の障害を示すものではない。
   robots.txtは全クローラーを明示的に許可している）。

   否定できる。残る原因は「①まだGoogleにクロール・インデックスされて
   いない」か「②インデックス済みだが個別施設名クエリでは順位が低く
   出てこない」のいずれか（またはその両方）で、この2つの切り分けは
   GSCの「URL検査」でのみ可能（下記5参照）。**→ 2026-08-31中に運用者が
   URL検査を実施し、②で確定した（下記7参照）。**

   2026-08-31時点で全件確認済みのため、次回以降の定点観測では毎回
